# [P1] 剩余金额不够最小请求开销时仍发送，小额护栏失效

状态：已处理（2026-10-30）。审查日期：2026-10-30。审查提交：cdff07e。

## 位置

src/engine.js:467–499；src/prompts.js 的固定会话前缀及系统、输出指令构造。

## 证据

运行 `node scripts/review-throughput.js`，查看 `tiny-money-current`。

配置单路并发、金额上限 **0.00001 美元**、最多 1 次调用、10 秒截止，输入每百万 1 美元、输出每百万 2 美元。该正数金额可被服务端正常接受。

当前仍发送一次请求，模拟器按收到文本估算输入 560、回报输出 32，结算费用 **0.000624 美元**，约为上限 **62.4 倍**。随机文本会造成小幅变化；这个模拟验证的是本地护栏，不是真实厂商账单。

## 原因与影响

金额缩放后强制把输出抬回最低 32，却不再检查新费用是否仍超过剩余额度。后面的“输出低于最低值”检查因此无法拦截这个路径。

此外，文本规划可以缩到低于固定提示开销，但实际请求始终包含随机会话前缀、系统和输出指令。即使填充为空也不是零输入，现有预扣没有覆盖这个最低开销。

该条件也可能出现在正常大额运行的最后几笔，而不只是人为输入极小目标。扩大并发会放大未预扣的固定开销，因此应在吞吐优化前处理。

## 建议

先计算最小合法请求的保守成本；剩余额度不足时等待已有请求结算或结束。规划必须包含实际固定内容、最低输出及预扣余量；所有缩放结束后重新检查金额、总量与上下文限制，不能通过向上取最低输出绕过校验。

## 验收

覆盖接近零的正数金额、普通运行的尾款、无填充、较大固定提示、多路并发。若连最小合法请求都无法容纳，本地模拟服务应收到 **0 次**额外请求。断言每个计划的预扣覆盖全部已知开销，同时保留对真实分词和定价误差的诚实说明。

## 修复记录

规划前构造实际固定提示并计入协议余量，最低输出不再被缩放掉；只有最小合法请求能在金额与总量预留内放下时才发送。每次预扣和发送前均复核边界，未知开销不会被释放给重试。专项模拟极小金额收到 0 次请求；0.001 美元尾款场景只发出 1 次，结算约 0.000805 美元，随后因不足最小请求而结束。

复现脚本已改为验证修复后的回归断言；原始失败数字保留在本文作为历史证据。完整自测 46/46 通过，本轮专项 15/15 通过，均使用本地模拟服务。
