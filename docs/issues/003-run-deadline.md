# [P1] 运行时长到期不会主动取消正在等待的调用

状态：已修复（2026-10-29）。验证方式：本地模拟与当前代码路径核验。审查日期：2026-10-29。

## 位置

src/engine.js:180–185、573–580、668–670。行号以审查时工作区为准。

## 现象与证据

本地模拟服务保持连接但不结束；运行时限为 100 毫秒。366 毫秒后仍为运行状态，共享取消信号也未触发，需手动停止才能退出。

## 原因与影响

运行截止时间只在工作线程进入下一轮时检查；周期回调只采样和推送状态。所有线程都在等待响应时，没有独立机制触发截止处理。

单次响应可使运行明显超过用户设定的时长；连续有数据的长响应也不受空闲检查约束。

## 复现步骤

1. 配置一个不会结束的本地流式响应。
2. 单工作线程运行，设置较短的运行时限和较长的单次调用超时。
3. 超过运行时限后检查运行状态和取消信号。

## 修复建议

启动时设置独立截止计时器，或将剩余运行时长合并到调用取消信号；结束时清理计时器。

## 验收标准

即使所有线程都在等待响应，到期后也须在合理调度误差内触发本地取消并进入完成状态。

## 修复记录

`run()` 启动时设置独立的 `setTimeout` 截止计时器，到点直接 `stop()`，不依赖 worker 循环；结束清理。
