# [P1] 重试未计入次数护栏，实际调用数高于设定上限

状态：已修复（2026-10-29）。验证方式：本地模拟与当前代码路径核验。审查日期：2026-10-29。

## 位置

src/engine.js:265–301、419–433；各协议的参数回退循环。行号以审查时工作区为准。

## 现象与证据

次数上限为 1、单工作线程、允许两次重试。模拟服务先返回两次 500，再成功。上游实际收到 3 次调用，最终次数账本却为 1，另记重试数为 2。

## 原因与影响

次数只在整个计划最终成功或失败时加一，内部重试沿用同一笔次数预扣；协议参数变体也可能发出多次实际调用。

次数硬顶约束的是逻辑计划，而不是实际发送次数；连接中断后的重新发送还可能对应已发生但未结算的上游工作。

## 复现步骤

1. 设置模拟服务前两次返回临时错误、第三次成功。
2. 设置次数上限 1、并发 1、允许两次重试。
3. 比较模拟服务收到的调用数和最终账本。

## 修复建议

每次实际发送前预扣一次调用额度，重试和参数回退都经过统一入口；需要保留逻辑计划数时另设统计字段。

## 验收标准

次数上限为 1 时，上游最多收到一次调用；重试需要剩余额度，不能越过硬顶。

## 修复记录

新增 `wire` 计数，每次实际 HTTP 调用（含重试与参数变体回退）前预扣，次数硬顶按真实调用计。
