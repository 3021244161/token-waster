# [P2] 运行报告的费用明细未换汇，导致分项与合计不一致

状态：已修复（2026-10-29）。验证方式：本地模拟与当前代码路径核验。审查日期：2026-10-29。

## 位置

src/report.js:80–89、258–261。行号以审查时工作区为准。

## 现象与证据

输入单价为人民币 1、输出单价为人民币 2，输入输出各为 1,000,000。按项目汇率合计为美元 0.4167；报告输入分项却显示美元 1.0000，输出分项显示美元 2.0000。

## 原因与影响

明细直接将原币种费用传给固定美元格式化函数，合计却使用引擎已经换算的美元金额。

报告中的分项合计与总费用不符，对采用人民币价格的服务尤其明显，导出后的账单信息会误导读者。

## 复现步骤

1. 构造人民币计价、输入输出均有使用量的报告数据。
2. 使总费用采用引擎相同汇率换算后的美元值。
3. 比较两项费用明细与总费用。

## 修复建议

所有明细统一转换为美元后展示，或统一使用原币种并单独展示换汇合计；复用现有换汇计算，避免两套公式。

## 验收标准

人民币与美元计价的数据都应满足明细之和与合计在显示精度内一致。

## 修复记录

分项金额按汇率折算为与合计一致的美元，单价列同时标注原币与美元。
