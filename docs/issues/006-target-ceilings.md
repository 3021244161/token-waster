# [P1] 目标值绕过服务端声明的金额与次数硬顶

状态：已修复（2026-10-29）。验证方式：本地模拟与当前代码路径核验。审查日期：2026-10-29。

## 位置

server.js:148–163、177–182。行号以审查时工作区为准。

## 现象与证据

空跑配置中，金额目标设为 1,000 时被接受，最终金额限制为 1,000，超过声明的 500；次数目标设为 30,000 时也被接受，超过声明的 20,000。次数场景另设了有限时长。

## 原因与影响

额外护栏字段经过硬顶裁剪，但直接目标值只受通用大数限制；之后直接赋给对应运行限制。

相同限制因入口不同具有不同安全边界，用户可以从正常目标字段越过界面和服务端声明的最高额度。

## 复现步骤

1. 使用空跑模式，将金额目标设为 1,000，其他金额护栏留零。
2. 检查状态返回的生效金额限制。
3. 再将次数目标设为 30,000，附加有限时长，检查生效次数限制。

## 修复建议

合并目标和额外护栏后，对最终生效值统一执行硬顶裁剪或拒绝超限配置。

## 验收标准

任何模式和字段组合均不能产生大于 500 的金额限制或大于 20,000 的次数限制。

## 修复记录

目标值与护栏合并后统一执行硬顶裁剪（金额 500 / 请求 20000 / 时长 6h），任何入口都无法越过。
