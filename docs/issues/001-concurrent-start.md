# [P1] 并行启动会留下无法由停止按钮管理的运行

状态：已修复（2026-10-29）。验证方式：本地模拟与当前代码路径核验。审查日期：2026-10-29。

## 位置

server.js:311–321。行号以审查时工作区为准。

## 现象与证据

将两次启动请求的正文分段发送，使两次运行状态检查都先于正文读取完成。两次响应均为 202；模拟服务观察到两条活动连接。调用停止后，当前状态变为完成，但第一条连接仍然存在。

## 原因与影响

排他检查位于异步读取正文之前；读取完成后未重新检查。后启动的实例覆盖全局运行引用，较早实例仍在执行。

界面只管理最后一个实例，停止按钮和统计无法覆盖全部工作；每次运行的并发与额度限制也不能构成整个进程的限制。

## 复现步骤

1. 准备一个接收调用后保持流式连接的本地模拟服务。
2. 同时建立两次启动请求，各先发送正文的首个字符。
3. 等待两次处理函数均进入正文读取，再补齐正文；观察两个 202。
4. 发出停止指令，检查当前状态与模拟服务中剩余的活动连接。

## 修复建议

在完成正文读取后、写入运行引用之前进行同步排他检查，或为启动过程设置独占状态；停止时始终管理全部已启动实例。

## 验收标准

并行提交两次启动时仅允许一次成功，另一次返回 409；停止后本地所有上游连接均已取消。

## 修复记录

用 `starting` 独占标志把「检查—读正文—安装实例」整段串行化；启动窗口内第二个请求返回 409。验证：两个半包请求并发提交，一个 202、一个 409。
